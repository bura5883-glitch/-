# CTAパターン集（導線担当が管理）

- 最終更新: 2026-09-24（AIツール検証ジャンル向けに拡充）
- 前提: `strategy.md`（AIツール（SaaS）× 業務効率化／匿名の「検証係」／主チャネルX）
- 導線の全体像: **X投稿 → プロフィール → 固定投稿／リンク集（lit.link等） → note・ブログの比較記事 → 公式サイト（ASPリンク）**
- プロフィール・固定投稿・リンク集・計測設計は `cta/profile.md` にまとめている

## 共通ルール
1. **1投稿につきCTAは1つだけ。** 「フォローして＋リプ欄も見て＋保存して」のように複数の行動を求めない
2. **読者のメリットが先、行動のお願いは後。** 計測結果・画面・向かない人を先に出し、CTAは最後の1行に置く
3. **Xの本文にはリンクを貼らない（全フェーズ共通）。** リンクはリプライ欄、プロフィール、リンク集、note・ブログに置く
4. **ASPリンク（案件リンク）を置く導線には必ず【PR】を付ける。** 詳しくは下の「PR表記ルール」
5. **CTA IDを投稿ファイルに書く。** `posts/*.md` の各投稿に `CTA: CTA-05` のように記録し、`reports/metrics.csv` の数値と突き合わせて型ごとの効き目を比べる
6. NG表現（「誰でも」「必ず」「◯分で完成」「作業時間ゼロ」「最強」「これ一択」「稼げる」）はCTA文にも使わない

|---|---|---|---|---|---|

| CTA-02 | プロフ誘導 | ◎ | ◎ | ○ | なし（プロフィールへ） |

| CTA-04 | 比較記事誘導 | × | ◎（note） | ◎（note・ブログ） | リプ欄 or リンク集: 比較記事 |

| CTA-07 | 検証リクエスト募集 | ◎ | ○ | ○ | なし（リプライを募る） |

**フェーズごとの配分の目安（仮。30日ごとに実績を見て見直す）**
- **0〜30日:** CTA-05・06・07・02 を中心に回す。目的は「フォロー」と「プロフィール遷移」。案件リンクは原則出さない
- **31〜90日:** CTA-04（note比較記事）を柱にし、検証ポストの2〜3本に1本はCTA-01・04で記事や公式サイトへ送る。CTA-10はカウンセリング受講後に解禁
- **91〜180日:** CTA-04の送り先にブログを追加。反応の良かった型に寄せ、クリック率の低い型は減らす

## 各型の詳細

### CTA-01 リプ欄誘導
- **使う場面:** 本文で検証結果（時間・画面・向かない人）を出し切った投稿。「どのツール？」と聞かれそうなとき
- **フェーズ:** 0〜30日は案件でないリンク（公式サイト・公式ヘルプ）だけ。ASPリンクは「ASP承認済み・X媒体登録済み・SNS掲載可」を満たす案件に限り、月末に1〜2回だけ試す。31日〜は本格的に使う
- **文例（本文の最後）:** 「今回使ったツールと、試したプランはリプ欄に置いておきます」
- **文例（リプライ／ASPリンクの場合）:**
  > 【PR】今回使ったツール（有料プラン・1か月分を自腹で契約）
  > ※このリンクから登録されると、筆者に報酬が入ります
  > （リンク）
- **NG例:** 本文にリンクを貼る／リプ欄にASPリンクがあるのに本文とリプライに【PR】がない／同じリンク付きリプライを複数の投稿に連投する／他人の投稿へのリプライでリンクを貼る

### CTA-02 プロフ誘導
- **使う場面:** シリーズ投稿、検証ルールの紹介、ある程度数字が伸びた投稿。まとめた情報が固定投稿やリンク集にあるとき
- **文例:** 「作業ごとの検証の一覧は、プロフィールの固定ポストにまとめています」
- **NG例:** 毎投稿で連発する／「プロフ見て！」だけで、行くと何が得られるかを書かない／プロフィール先に特定商品を勧める導線があるのに、その商品を推す投稿に【PR】を付けない

### CTA-03 無料特典（計測シート配布）
- **使う場面:** 「AIなし／ありで作業時間を測る」系の投稿。読者が自分でも測りたくなる内容のとき
- **特典の中身:** オーナーが実際に使っている**作業時間の計測シート**（Googleスプレッドシートのコピー用リンク）。メールアドレス登録などの個人情報は求めない
- **置き場所:** 0〜30日はリンク集（プロフィールのリンク）経由。本文にはリンクを貼らない
- **文例:** 「今回使った計測シート（作業名・AIなし・AIあり・差分を入れるだけ）は、プロフィールのリンク集から無料でコピーできます」
- **NG例:** 「これを使えば誰でも時短」など、特典の効果を誇大に書く／特典と引き換えにフォローやリポストを求める（キャンペーン扱いになりXのルールとぶつかる恐れ）／使っていないテンプレートを配る

### CTA-04 比較記事誘導
- **使う場面:** 同じ作業テーマ（例: 議事録）で検証ポストが3本以上たまり、note・ブログにまとめたとき
- **フェーズ:** 31日〜（noteの開始後）。91日〜はブログの記事も送り先にする
- **文例（本文の最後）:** 「議事録AI 3つを同じ60分の会議音声で比べた表と、向かない人の条件をnoteにまとめました。リンクはリプ欄に置きます」
- **文例（リプライ）:** 「【PR】比較記事（記事内に広告リンクを含みます）（リンク）」
- **NG例:** 記事に案件リンクがあるのに、誘導ポストで何も触れない／「完全版」「これ一択」とあおる／まだ検証していないツールを比較表に入れる

### CTA-05 フォロー誘導（シリーズ予告）
- **使う場面:** 週の検証テーマを予告するとき、シリーズの1本目・途中
- **文例:** 「来週は同じ資料を3つのスライド生成AIで作って、修正にかかった時間まで測ります。続きを見たい人はフォローしておいてください」
- **NG例:** 「フォローした人だけに特典」のような条件付け／予告した検証をやらない／毎投稿の末尾に定型で「フォローしてね」を付ける

### CTA-06 保存（ブックマーク）誘導
- **使う場面:** 手順・設定・プロンプト・「向かない人」のチェックリストなど、あとで見返す価値のある投稿
- **文例:** 「実際に試すときに見返せるよう、ブックマークしておくと便利です」
- **NG例:** 保存する価値のない感想ポストで使う／「保存必須」「保存しないと損」と不安をあおる

### CTA-07 検証リクエスト募集
- **使う場面:** 検証のネタを集めたいとき、フォロワーとの接点を増やしたいとき。0〜30日の関係づくりに特に向く
- **文例:** 「次に『AIなし／あり』で測ってほしい作業があれば、リプで教えてください。毎週の検証テーマの候補にします」
- **NG例:** 集めたリクエストを無視し続ける／リクエスト主の個人情報や業務内容を本人の同意なく晒す／案件にしたい商品へ誘導するための「やらせ」のリクエストを装う

### CTA-08 スレッド続き誘導
- **使う場面:** 週1本の長めのスレッド。1投稿目で結論（何分→何分・条件つき）を先に見せ、続きで手順や画面を出す
- **文例（1投稿目の最後）:** 「手順と、うまくいかなかった点はこのスレッドに続けます」
- **NG例:** 1投稿目で結論を隠して引っぱる（「結果は…続きで」）／スレッドの途中に案件リンクを入れるのに1投稿目に【PR】がない

### CTA-09 過去の検証への引用誘導
- **使う場面:** 同じ作業テーマの続編、再検証（アップデート後にもう一度測った等）。自分の過去ポストを引用する形なので外部リンクにならない
- **文例:** 「前回、同じ作業をAIなしで測った結果がこちら。今回はAIありで同じ条件で測りました」
- **NG例:** 自分の古いポストの引用を毎日くり返す／条件の違う検証結果を並べて、同じ条件で比べたように見せる

### CTA-10 無料相談の記録誘導（生成AIスクール）
- **使う場面:** オーナー自身が無料カウンセリングを受け、聞かれたこと・提案内容・勧誘の強さを記録したあと
- **フェーズ:** 受講後のみ（`strategy.md` 判断待ち2の決定に従う）。受講していない段階では使わない
- **文例（本文）:** 「生成AIスクールの無料カウンセリングを実際に受けてきました。聞かれたこと、すすめられたコース、勧誘の強さを記録にまとめています。※私は受講はしていません。記録はリプ欄に置きます」
- **文例（リプライ）:** 「【PR】無料カウンセリングの記録（記事内に申込ページへの広告リンクを含みます）（リンク）」
- **NG例:** 「無料で学べる」「無料で受講できる」と読める書き方（無料なのは相談だけ）／受講していないのに受講したように書く／「今だけ」「残りわずか」など確認していない期限であおる／「AIで副業」「稼げるようになる」と結びつける

## PR表記ルール（どこに・どう書くか）

根拠: 景品表示法のステマ規制（2023年10月施行）。アフィリエイトで報酬を得る紹介は「広告」にあたるため、一般の読者が広告だと分かる表示が必要。**迷ったら付ける。**

### いつ付けるか
- **案件リンク（ASPリンク）がある投稿・リプライ・記事・リンク集には必ず付ける**
- **特定の案件商品を勧めていて、その先（リプ欄・プロフィール・note・ブログ）に案件リンクがある導線の投稿にも付ける**（本文にリンクがなくても、報酬につながる紹介なら広告として扱う）
- 付けなくてよいもの: 案件と無関係の検証ポスト、案件にしていないツールの話、フォロー・保存・リクエスト募集だけの投稿
- 広告主から無料アカウント・無料期間・謝礼などの提供を受けた場合は、「自腹」と書かず「提供を受けて検証」と明記し、【PR】を付ける

### どこに書くか
| 場所 | 書く位置 | 書き方 |
|---|---|---|
| Xの投稿（本文） | **先頭** | 「【PR】」から始める |
| Xのリプライ（リンクを置く側） | **先頭** | 「【PR】」＋「このリンクから登録されると筆者に報酬が入ります」 |
| リプ欄にASPリンクを置く投稿の本文 | **先頭** | 本文とリプライの**両方**に【PR】 |
| スレッド | **1投稿目の先頭**と、**リンクを置く投稿の先頭** | 途中からだけ広告になるのを防ぐ |
| 画像・動画 | 本文の先頭（画像内の表記だけに頼らない） | 画像内にも入れる場合は、小さくしない・端に寄せない |
| Xのプロフィール | 自己紹介文の中 | 「案件リンクを含む投稿は【PR】表記」 |
| 固定投稿 | 検証ルールの一項目として | PR表記ポリシーを明記（`cta/profile.md` 参照） |
| lit.link等のリンク集 | 案件リンクを含む**ブロックの見出し**と、ページ上部 | 見出し「【PR】使っているツール」／上部に「このページには広告リンクを含みます」 |
| note | **タイトルの先頭**と、**本文の1行目（最初のリンクより前）** | タイトル「【PR】」＋本文冒頭「この記事には広告（アフィリエイトリンク）を含みます」 |
| ブログ | 記事タイトル直下（スクロールせずに見える位置） | 「本記事は広告（アフィリエイトリンク）を含みます」 |

### どう書くか
- 使う文言は **「【PR】」または「【広告】」** に統一する（読者に一目で伝わるもの）
- **OK:** 本文の先頭に【PR】／リンクの直前に「広告」と明記／報酬が入る旨を一言添える
- **NG:**
  - 本文の末尾や、大量のハッシュタグの中に「#PR」を埋もれさせる
  - 「提携」「アンバサダー」「紹介」など、広告だと分かりにくい言葉だけで済ませる
  - 画像の隅に小さく入れるだけ／背景と同じ色で見えにくくする
  - 「続きを読む」の折りたたみの下や、記事の最後だけに書く
  - 【PR】を付けたうえで「広告ではありません」「ガチの本音です（報酬なし）」のように打ち消す
- PR表記があっても、優良誤認（「誰でも」「必ず」「◯分で完成」など）は別に違反になる。表記とNG表現チェックはセットで行う
