# 古着転売トラッカー

元手10,000円から始める古着販売とSNS発信を管理する、ビルド不要の静的ウェブアプリです。
[事業計画書](docs/事業計画書.md)の「管理項目」をそのまま週次で追えるように作っています。

## 使い方

`index.html` をブラウザで開くだけで動きます。サーバーもインストールも不要です。

```
open index.html          # macOS
xdg-open index.html      # Linux
python3 -m http.server   # ローカルサーバーで開く場合
```

記録は開いた端末のブラウザ（localStorage）にのみ保存されます。
端末を変えるときや、消えると困るタイミングでは「データ・計画」タブからJSONを書き出してください。

## 画面

| タブ | 内容 |
| --- | --- |
| ダッシュボード | 総資産・現金残高・在庫・利益率・フォロワーのKPI、総資産の推移、週ごとの純利益、今週の投稿ノルマ、利益の大きかった商品 |
| 商品・在庫 | 仕入れの登録、在庫と売却済みの一覧、販売登録（手数料の自動計算つき） |
| SNS | 投稿とフォロワー数の記録、フォロワー推移、週ごとの総再生数 |
| 週次レポート | 管理項目11種を月曜〜日曜の週単位で集計した表。CSV書き出し対応 |
| データ・計画 | JSONの書き出し・読み込み・全削除、運営ルールとスケジュールの確認 |

## 計算のしかた

事業計画書の「手数料・送料を含めて利益を管理する」に合わせ、利益は必ず手数料と送料を引いた後の額です。

```
1商品の利益 = 売値 − 手数料 − 送料 − 仕入値
現金残高   = 10,000円 − 仕入れ総額 + (売上 − 手数料 − 送料)
総資産     = 現金残高 + 在庫の仕入れ原価
総利益     = 総資産 − 10,000円
```

在庫は仕入れ原価で評価します。売れるまでは利益として数えないので、
「在庫を高く見積もって儲かっているように見える」ことがありません。

## 運営ルールのチェック

ダッシュボードの上部に、ルールから外れている点が警告として出ます。

- 現金残高がマイナス（追加資金なしのルール違反）
- 正規品の確認が未チェックの商品
- 商品状態が未記入の商品
- 仕入れから30日以上動いていない在庫

仕入れ登録時に現金残高を超える金額を入力した場合も、登録前に確認が入ります。
